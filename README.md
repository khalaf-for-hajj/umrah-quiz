# مسابقة المعتمرين — حملة الخلف

تطبيق ويب عربي (RTL) للجوال لإدارة مسابقة فقهية وثقافية يشارك فيها المعتمرون من هواتفهم داخل الباصات.
ملفّان فقط + الشعار، بلا أي أدوات بناء، ويعمل على **GitHub Pages** مع **Supabase** (الخطة المجانية).

| الملف | الوظيفة |
|---|---|
| `index.html` | التطبيق كاملاً: واجهة المشترك + لوحة المشرف على `#/admin` |
| `schema.sql` | الجداول والأمان (RLS) والدوال في قاعدة البيانات |
| `logo.png` | الشعار الافتراضي (يمكن تغييره من الإعدادات) |

> **جرّب أولاً بلا أي إعداد:** افتح `index.html` من خادم محلي أو من GitHub Pages قبل ضبط Supabase، وسيعمل بوضع تجريبي (بيانات محلية في المتصفح مع شريط تنبيه أصفر) لمعاينة الواجهة. لوحة المشرف في هذا الوضع تفتح مباشرة بلا كلمة مرور.

---

## 1) إنشاء مشروع Supabase

1. أنشئ حساباً مجانياً في [supabase.com](https://supabase.com) ثم **New project** (اختر منطقة قريبة، واحفظ كلمة مرور قاعدة البيانات).
2. انتظر حتى يكتمل تجهيز المشروع.

## 2) تشغيل `schema.sql`

1. افتح `schema.sql` بأي محرر وابحث عن هذا السطر (قرب نهاية القسم 7):

   ```sql
   insert into public.admins (email) values ('change-me@example.invalid') on conflict do nothing;
   ```

2. **غيّر البريد إلى بريدك الحقيقي** بحروف صغيرة (ويمكنك إضافة أكثر من سطر لعدة مشرفين).
3. في Supabase: **SQL Editor ← New query**، الصق محتوى الملف كاملاً واضغط **Run**.
   الملف آمن لإعادة التشغيل (لا يحذف بياناتك الموجودة).
4. سيُضاف تلقائياً 8 أسئلة تجريبية في فقه العمرة وثقافتها وباصان (1 و2) **للتجربة فقط** — احذفها من لوحة المشرف قبل الإطلاق.

## 3) إنشاء حساب المشرف

1. **Authentication ← Users ← Add user ← Create new user**.
2. أدخل **نفس البريد** الذي وضعته في `schema.sql` وكلمة مرور قوية، وفعّل خيار **Auto Confirm User**.
3. **أغلق التسجيل العام** حتى لا يستطيع أحد إنشاء حساب: **Authentication ← Sign In / Providers** (أو Settings) ← أوقف **Allow new users to sign up**.
   (حتى لو أُنشئ حساب، فلن تعمل صلاحيات المشرف إلا لبريد موجود في جدول `admins`.)

## 4) ربط التطبيق

1. من **Project Settings ← API** انسخ **Project URL** و **anon public key**.
2. افتح `index.html` وابحث عن الكتلة `CONFIG` في أعلى السكربت:

   ```js
   const CONFIG = {
     SUPABASE_URL: '',        // https://xxxx.supabase.co
     SUPABASE_ANON_KEY: '',   // eyJ...
     TIMEZONE: 'Asia/Riyadh',
   };
   ```

3. الصق القيمتين فقط. ⚠️ **لا تضع أبداً** مفتاح `service_role` أو أي مفتاح سري؛ مفتاح `anon` مصمَّم ليكون علنياً، والحماية تتم في قاعدة البيانات.

## 5) النشر على GitHub Pages

1. أنشئ مستودعاً جديداً وارفع `index.html` و `logo.png` (و `schema.sql` و `README.md` اختيارياً) إلى الجذر.
2. **Settings ← Pages ← Deploy from a branch ← main / (root)**.
3. بعد دقيقة يصبح الرابط `https://اسمك.github.io/اسم-المستودع/`.
4. لوحة المشرف: أضف `#/admin` إلى الرابط، وسجّل الدخول ببريد المشرف.
5. من الصفحة الرئيسية للوحة ستجد بطاقة **رابط المسابقة** مع QR وزر نسخ لتوزيعه على الباصات.

## الاستخدام اليومي

**قبل المسابقة**
1. **الأسئلة:** احذف الأسئلة التجريبية وأضف أسئلتك (يدوياً، أو استيراد Excel/CSV، أو لصق نص). يمكن تحديد «عدد الأسئلة لكل محاولة» من الإعدادات ليحصل كل مشترك على عدد عشوائي منها.
2. **الباصات والمشتركون:** احذف الباصين التجريبيين، ثم استورد المشتركين من Excel/CSV (الأعمدة: الاسم، الجوال، الجنس ذكر/أنثى، رقم الباص). تظهر معاينة تكشف الأرقام الخاطئة والمكرر قبل الحفظ، وتُنشأ الباصات الناقصة تلقائياً. زر «تحميل نموذج» يعطيك الملف الجاهز.
3. **الإعدادات:** اسم الحملة، الشعار، اللون، مدة السؤال، النقاط، التسجيل الذاتي، إظهار النقاط/الصح والخطأ.
4. **التجربة:** فعّل **وضع التجربة** (والمسابقة ما تزال مسودة)، جرّب المشاركة بجوالك، ثم اضغط **حذف بيانات التجربة** (بتأكيدين). لا يمكن فتح المسابقة وبيانات التجربة موجودة.

**يوم المسابقة**
- افتحها يدوياً من الصفحة الرئيسية (**فتح المسابقة الآن**)، أو حدّد وقتي البداية والنهاية من الإعدادات ثم **تفعيل الجدولة** (يظهر للمشتركين عدّاد تنازلي).
- تابع المشاركة لكل باص والترتيب المباشر من لوحة المشرف.
- اضغط **إنهاء المسابقة الآن** (أو انتظر وقت النهاية)؛ تُغلق المحاولات الجارية وتُحتسب.

**بعد المسابقة**
- من **النتائج**: راجع الجدول وصدّره Excel أو اطبعه، ثم **نشر النتائج** ليرى كل مشترك ترتيبه وقائمة المتصدرين ومراجعة إجاباته مع الشرح. (يمكن **إخفاؤها** لاحقاً.)
- **🏆 إعلان الفائزين:** شاشة كاملة بمنصة تتويج متحركة لأول 3 (مجتمعين، أو رجال ونساء منفصلين) — مناسبة للعرض على شاشة كبيرة. زر Esc يغلقها.

## كيف يعمل التحكيم والحماية

- **الإجابات الصحيحة لا تصل المتصفح أبداً**؛ تُحفظ في جدول منفصل لا يقرؤه إلا المشرف، ويصحّح الخادم كل إجابة.
- الزمن محسوب **على الخادم**؛ الإجابة المتأخرة لا تُقبل، وإغلاق المتصفح لا يوقف العدّاد. من أغلق الصفحة يعود بإدخال رقمه ويكمل من السؤال الحالي.
- لكل مشترك ترتيب أسئلة واختيارات عشوائي مختلف، والمحاولة **مرة واحدة لكل رقم جوال** (قيد فريد في القاعدة).
- **النقاط:** إجابة صحيحة = 100 (قابلة للتعديل) + مكافأة سرعة تصل إلى 50 بحسب الوقت المتبقي، والخطأ أو عدم الإجابة = 0. **الترتيب:** الأعلى نقاطاً، ثم الأقل زمناً، ثم الأسبق إنهاءً.
- إن صحّحت إجابة خاطئة في سؤال بعد بدء المشاركات فاستخدم **إعادة تصحيح الإجابات** من الإعدادات.

## ملاحظات مهمة

- حالات المسابقة: **مسودة ← مفتوحة ← مغلقة ← منشورة النتائج**. لا يُنشر شيء قبل الإنهاء.
- أرقام الجوال تُوحَّد تلقائياً (05xxxxxxxx / 5xxxxxxxx / +9665… / 009665… والأرقام العربية). الأرقام الدولية الأخرى مقبولة كما هي.
- يحتاج التطبيق اتصالاً بالإنترنت؛ عند انقطاع الشبكة تُعاد المحاولة تلقائياً دون ضياع الإجابة ما دام وقت السؤال لم ينتهِ.
- المكتبات الخارجية (Supabase، SheetJS، QR، خط Tajawal) تُحمَّل من CDN عند الحاجة فقط.
- الشعار المرفوع يُضغط في المتصفح ويُحفظ ضمن الإعدادات (حد أقصى 200KB).
- الخطة المجانية في Supabase تتوقف عن المشروع بعد أسبوع من الخمول؛ افتح لوحة المشرف قبل المسابقة بيوم للتأكد أنه يعمل.
